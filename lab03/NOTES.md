сравнение версий:

git diff показывает разницу между конкретными состояниями файлов. 

git show выводит информацию об одном конкретном коммите (кто, когда и какие именно строки поменял). 

git log просто выводит список истории. 
команда 

git log -S ищет по истории коммиты, в которых добавлялась или удалялась конкретная строка (например, def). 

команда git blame показывает, кто и в каком коммите написал каждую отдельную строчку в файле.

восстановление:
обычный git restore просто отменяет незафиксированные изменения, возвращая файл к состоянию последнего коммита. 

git restore --source=... берет файл из указанного старого коммита и заменяет им текущий файл в рабочей папке. если бы в файле были важные несохраненные правки, обе эти команды стерли бы их безвозвратно.

отмена коммита:
git revert создает новый коммит, который делает изменения, обратные ошибочному коммиту, сохраняя при этом всю историю. 

git reset --hard удаляет коммиты, переписывая историю назад. в опубликованном репозитории безопаснее использовать revert, чтобы не сломать историю коммитов другим людям, которые уже могли ее скачать.

теги:
тег — это постоянное имя для коммита, которое фиксируется навсегда. ветка же постоянно сдвигается вперед при каждом новом коммите.
